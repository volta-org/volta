## Определение сущностей

### Сущности и атрибуты

- User - запись о пользователе в системе

    Атрибуты: UserID, Login, Rights, Name, Surname, Email

- TestConfig - параметры запуска теста

    Атрибуты: ConfigID, RPS, Duration, URL, LoadType

- TestStats - срез метрик, пишется раз в секунду

    Атрибуты: Timestamp, TestID, RPS, ErrorsPerSec, Latency, p50, p95, p99

- Test - агрегат всех срезов

    Атрибуты: TestID, ConfigID, TotalRequests, TotalErrors, p50, p95, p99, Status

- TestAnalysis - результат AI-анализа завершенного теста

    Атрибуты: ID, TestID, Status, Summary, Anomalies (список), Recommendations (список)

### Акторы и характер взаимодействия

| Сущность     | Акторы (Действие)                                                               | Характер                                                   |
|--------------|---------------------------------------------------------------------------------|------------------------------------------------------------|
| User         | Admin (CRUD)                                                                    | Транзакционный                                             |
| TestConfig   | Система (создание при запуске)                                                  | Транзакционный                                             |
| Test         | QA/Dev (просмотр, запуск), система (запись результатов)                         | Транзакционный, аналитический (просмтотр истории запусков) |
| TestStats    | Система (запись каждую секунду), UI (чтение в реальном времени и ретроспектива) | Потоковый, аналитический (просмотр истории срезов)         |
| TestAnalysis | AI-модуль (запись), Dev/QA (чтение)                                             | Транзакционный (запись), аналитический (чтение)            |

## Выбор технологий хранения

| Шаг                          | User                                                | TestConfig                                         | Test                                                    | TestStats                                            | TestAnalysis                                             |
|------------------------------|-----------------------------------------------------|----------------------------------------------------|---------------------------------------------------------|------------------------------------------------------|----------------------------------------------------------|
| Сколько данных?              | < 1 ГБ (число QA/Dev * размер User)                 | < 1 ГБ                                             | < 10 ГБ (десятки тысяч тестов)                          | 10 ГБ - 1 ТБ (RPS * Duration * число тестов)         | < 10 ГБ (поля Summary/Anomalies могут быть большими)     |
| Паттерн записи/чтения        | OLTP (редкая запись, частое чтение при отображении) | OLTP (однократная запись, чтение при старте теста) | OLTP (запись при старте/финише, чтение при отображении) | Write-heavy                                          | OLAP (анализ рекомендаций)                               |
| Требования к консистентности | Strong                                              | Strong                                             | Strong                                                  | Eventual (потеря небольшого числа срезов некритична) | Eventual (анализ формируется асинхронно после теста)     |
| Требования к доступности     | 99.9% (достаточно)                                  | 99.9% (достаточно)                                 | 99.9% (достаточно)                                      | 99.9%+ (во время теста очень важна доступность)      | 99.9% (достаточно)                                       |
| Нужны транзакции?            | Да (смена прав атомарна)                            | Да                                                 | Да (старт теста и запись конфига идет как одно целое)   | Нет                                                  | Нет                                                      |
| Тип запросов                 | Поиск по (login, id), фильтрация                    | Поиск по (configId)                                | Поиск по (TestID), фильтрация                           | Поиск по временному диапазону                        | Поиск по (TestID), чтение всего документа                |
| Итоговое решение             | Реляционная БД                                      | Реляционная БД                                     | Реляционная БД                                          | TimeSeries БД                                        | Реляционная БД с JSON полем под Recomendations/Anomalies |

### Нужно подтвердить

У TestStats должен быть срок хранения. Спросить у QA как далеко в историю они реально заглядывают.
