## NFR-01: Производительность

**ID:** NFR-001

**Название:** Генерация нагрузки на одном узле

**Категория:** Performance Efficiency

**Приоритет:** Must Have

**Требование:**
Агент должен быть способен генерировать не менее 10,000 RPS при выделении 2 vCPU и 4 GB RAM

**Обоснование:**
Ключевое конкурентное преимущество Volta - экономия инфраструктуры за счет Virtual Threads. Если мы будем потреблять столько же ресурсов, сколько JMeter, продукт потеряет ценность для CTO.

## NFR-02: Надежность

**ID:** NFR-002

**Название:** Сохранность данных при сбое агента

**Категория:** Reliability

**Приоритет:** Should Have

**Требование:**
В случае аварийного завершения работы Агента во время теста, уже собранные метрики за период до сбоя должны быть сохранены в Мастере и доступны для анализа. Потеря данных не должна превышать 10 секунд.

**Обоснование:**
Нагрузочные тесты могут длиться часами. Потеря всех результатов из-за сбоя сети в конце теста недопустима.

## NFR-03: Безопасность

**ID:** NFR-003

**Название:** Локализация данных

**Категория:** Security

**Приоритет:** Must Have

**Требование:**
Система не должна отправлять никакие данные (логи, метрики, токены) во внешние сети или облачные сервисы, если это явно не включено администратором. Весь трафик между Мастером и Агентами должен находится в LAN.

**Обоснование:**
Основное требование банков и финтеха. Любая "утечка" телеметрии наружу приведет к запрету на использование ПО службой безопасности.

## NFR-04: Совместимость

**ID:** NFR-004

**Название:** Поддержка ОС

**Категория:** Portability

**Приоритет:** Should Have

**Требование:**
Агент должен запускаться и корректно работать на ОС Linux (Debian/RHEL), Windows Server 2019+ и macOS (ARM64/x86) без перекомпиляции.

**Обоснование:**
Разработчики часто запускают тесты локально на macOS/Windows, в то время как CI/CD агенты работают чаще всего на Linux.

## NFR-05: Удобство использования

**ID:** NFR-005

**Название:** Время отклика интерфейса при нагрузке

**Категория:** Usability / Performance

**Приоритет:** Should Have

**Требование:**
Графики в дашборде должны обновляться с частотой не реже 1 раза в секунду, при этом задержка отрисовки UI не должна превышать **200 мс.**

**Обоснование:**
QA-инженер должен видеть деградацию системы мгновенно, чтобы успеть остановить тест.

## Обоснование непокрытых категорий

**Не покрыты:**
- **Масштабируемость:** Для MVP мы ограничиваемся фиксированным кластером. В следующих версиях добавим.
- **Локализуемость:** В MVP интерфейс только на английском. Не критично. В следующих версиях при потребности добавим.
- **Сопровождаемость:** Это внутреннее требование к коду, не влияет на пользователя напрямую в MVP.
