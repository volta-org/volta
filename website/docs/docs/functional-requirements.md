## UC-01: Запуск нагрузочного теста

**ID:** FR-001

**Название:** Запуск нового нагрузочного теста через веб-интерфейс

**Акторы:** QA-инженер, DevOps-инженер

**Предусловия:**
1. Пользователь авторизован в системе.
2. К кластеру подключен минимум 1 активный Агент (статус Ready)

**Основной поток:**
1. Пользователь переходит в раздел "Новый тест".
2. Пользователь загружает сценарий нагрузки (YAML/JMX файл) или выбирает из шаблонов.
3. Пользователь задает параметры атаки:
   - Целевой URL
   - Количество VUsers
   - Duration
   - Профиль нагрузки
4. Пользователь нажимает кнопку "Запустить".
5. Система валидирует параметры и доступность агентов.
6. Система распределяет нагрузку между агентами и начинает тест.
7. Система перенаправляет пользователя на страницу "Live Dashboard" со статусом Running.

**Альтернативные потоки:**
- **Недостаточно агентов:** Если запрошенная нагрузка превышает возможности текущих агентов, Система выдает предупреждение: "Ресурсов недостаточно для 50k RPS. Максимум: 10k RPS". Пользователь подтверждает запуск с меньшей нагрузкой.

**Постусловия:**
- Тест запущен, агенты генерируют трафик.
- Метрики начали поступать в базу данных.

## UC-02: Анализ результатов тестирования

**ID:** FR-002

**Название:** Просмотр отчета о завершенном тесте с метриками

**Акторы:** QA-инженер, Backend-разработчик

**Предусловия:**
1. Нагрузочный тест завершен (статус Finished).

**Основной поток:**
1. Пользователь выбирает тест из "Истории запусков".
2. Система отображает сводный дашборд:
    - Средний RPS
    - Процент ошибок, перцентили p50, p95, p99
    - Максимальная задержка
3. Пользователь выбирает вкладку "Графики".
4. Система строит графики: RPS, Latency over Time, Throughput.
5. Пользователь нажимает кнопку "Экспорт в PDF".
6. Система генерирует файл отчета и отправляет на скачивание.

**Исключительные потоки:**
- **Данные повреждены:** Если часть метрик не сохранилась (сбой агента), Система показывает плашку: "Данные неполные. Агент-2 был недоступен".

**Постусловия:**
- Пользователь получил аналитику по проведенному тесту.

## UC-03: Управление доступом (RBAC)

**ID:** FR-003

**Название:** Назначение роли пользователю в проекте

**Акторы:** Администратор проекта

**Предусловия:**
1. Пользователь уже зарегистрирован в системе.
2. Администратор находится в разделе "Настройки команды".

**Основной поток:**
1. Администратор нажимает "Добавить участника".
2. Администратор вводит Email пользователя.
3. Администратор выбирает роль из списка:
    - Viewer (Только просмотр отчетов).
    - Editor (Запуск тестов).
    - Admin (Управление командой).
4. Система проверяет существование пользователя.
5. Система отправляет уведомление и добавляет пользователя в список участников.

**Постусловия:**
- Пользователь получил доступ к проекту с выбранной ролью.
